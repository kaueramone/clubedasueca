## Root cause
Production lacked TURNSTILE_SECRET_KEY. The login action rejected verification before checking credentials. The existing Cloudflare widget had the correct four root hostnames. Its existing secret was configured as a sensitive production environment variable; no key rotation or CAPTCHA bypass was performed. A Siteverify probe with an intentionally invalid response returned invalid-input-response, confirming the configured secret was recognized.

## Changes
- Controlled email field survives unsuccessful React form actions; password is cleared after every submitted attempt and visibility returns to hidden.
- Submit waits for a successful Turnstile callback. Controlled hidden token avoids duplicate unmanaged response fields during React form reset.
- Tokens are invalidated on expiry/provider failure and reset after submission. Script load failures expose retry.
- Server verification fails closed on missing/oversized tokens, missing configuration, HTTP failure and network errors; request timeout is 10 seconds.
- Portuguese feedback separates invalid credentials, unconfirmed email, rate limiting, expired verification and unavailable verification. Logs contain only verification error codes, never submitted credentials or tokens.
- Registration was adapted to the shared controlled token hook.
